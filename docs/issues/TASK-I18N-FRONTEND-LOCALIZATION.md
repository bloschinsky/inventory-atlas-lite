# TASK: Add Frontend i18n with English and Ukrainian

## Goal

Introduce proper frontend internationalization for Inventory Atlas Lite using Vue i18n.

The application is currently English-only and many UI strings are hardcoded directly in Vue components.

Add:

- English locale
- Ukrainian locale
- language selector in Settings
- persistent language preference
- locale-aware date/number/currency formatting

This task covers frontend/UI localization only.

Backend error-code localization is handled by the related follow-up task:

`TASK-I18N-BACKEND-ERROR-LOCALIZATION.md`

## Requirements

### 1. Add i18n infrastructure

Use `vue-i18n`.

Create a clean locale structure, for example:

```text
client/src/i18n/
  index.js
  locales/
    en.json
    uk.json
```

English remains the default locale.

Supported locales:

```text
en
uk
```

Do not use machine translation at runtime.

### 2. Language setting

Add an `Interface` section to the existing Settings page.

Add:

```text
Language
- English
- Українська
```

Requirements:

- language change applies immediately
- page reload is not required
- persist selection in `localStorage`
- preference is browser/device-local
- do not store the preference in SQLite
- if no saved preference exists, default to English

Suggested storage key:

```text
inventory-atlas.locale
```

### 3. Extract existing UI strings

Replace hardcoded user-facing frontend strings with translation keys.

Cover all existing user-visible application areas, including at minimum:

- navigation
- Dashboard
- Items list
- Item details
- Add/Edit item form
- AI Add Item
- Categories
- Settings
- Backup / restore
- About
- update UI
- QR code UI
- QR scanner
- print labels UI
- dialogs
- buttons
- form labels
- placeholders
- empty states
- confirmations generated by frontend
- success/error notices generated by frontend
- accessibility labels where user-facing text is present

Do not leave obvious English-only UI text in Vue templates or frontend JS.

Use structured translation keys, for example:

```text
items.title
items.add
items.fields.purchasePrice
items.fields.serialNumber
common.save
common.cancel
settings.language
```

### 4. Do not translate user data

Internationalization applies only to application UI.

Do not automatically translate:

- item names
- category names
- custom field names
- descriptions
- locations
- template names
- user-entered values
- serial numbers
- brands/models
- imported data

### 5. Locale-aware formatting

Centralize formatting helpers where appropriate.

Use the active locale for display formatting of:

- dates
- numbers
- monetary values

Prefer built-in `Intl` / vue-i18n formatting facilities.

Do not change stored values or API formats.

### 6. Pluralization

Use locale-aware pluralization where counts are displayed.

Avoid manual English-only ternaries where vue-i18n pluralization is appropriate.

### 7. Fallback behavior

Use English as fallback locale.

Missing Ukrainian keys must not break rendering.

The app should fall back to English and preferably produce a development warning instead of rendering an empty string.

### 8. Development rule

Update project agent/development guidance so future frontend work must:

- add translation keys for new user-facing UI
- provide both `en` and `uk` values
- avoid introducing new hardcoded UI strings

Update the appropriate project guidance file(s), including `AGENTS.md` if that is the canonical location.

Do not change unrelated development rules.

## Architecture Notes

Prefer normal vue-i18n usage:

```js
const { t } = useI18n()
```

Avoid ad-hoc global string maps.

Keep locale files grouped by feature.

Reuse generic keys such as:

```text
common.save
common.cancel
common.delete
common.edit
common.close
```

## Tests

Add/update tests for at least:

- English is default
- language can switch to Ukrainian
- selected language survives reload
- language change does not mutate user data
- fallback locale works
- locale-aware date formatting
- locale-aware numeric/currency formatting
- representative major pages render translated UI
- existing tests still pass

Update E2E selectors if tests currently depend on hardcoded English text.

Prefer stable roles/test selectors where practical.

## Acceptance Criteria

The task is complete when:

1. Vue i18n is installed and initialized.
2. English and Ukrainian locales exist.
3. Settings contains an Interface / Language selector.
4. Language switches immediately.
5. Selected language persists in `localStorage`.
6. Major existing frontend UI is covered by translation keys.
7. User-created data is never automatically translated.
8. Dates/numbers/currencies display according to active locale.
9. English is the fallback locale.
10. Project guidance requires new UI to be localized.
11. Existing functionality is unchanged.
12. Lint, unit tests, and E2E tests pass.

## Out of Scope

Do not include:

- backend error localization
- translating user-entered data
- automatic translation services
- languages beyond English and Ukrainian
- database-stored language preferences
